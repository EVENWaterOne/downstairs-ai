## 0. 定位

Downstairs 游戏本体负责 **建设、政策、住户满意度**。V0.2 不重复这些，而是同一个世界的 **另一个视角**：你作为新来的社区工作者走进楼下，和住户面对面说话，看见数字背后的人。

- 游戏端做了什么（建了熟食中心、收紧了配额），住户会在楼下 **表现出来、说出来**，按各自的立场和记忆解读。
- 满意度在游戏端是一个数；在 V0.2 里是陈阿姨不再下楼、Kumar 午休蹲在楼梯口、Aisyah 家的长桌没地方摆。
- 住户对 **你这个人** 的印象，从你们的对话和共同经历里长出来，和游戏端的数字不一定一致。

现阶段没有真的接游戏，所以做一个 **游戏端模拟器**，手动或按剧本推送"执行了什么政策、满意度怎么变"，用来测试。

## 1. 要验证的问题

| # | 问题 | 怎么看出来 |
|---|---|---|
| Q1 | 游戏端的变化能不能被住户合理地"活出来"？同一个政策，不同住户反应是否不同、是否符合各自立场？ | 推送同一事件，看五户的言行差异；有没有出现和满意度方向矛盾的表现 |
| Q2 | GM 会不会自主补全未定义的普通细节，而不是拒绝？（修 V0.1 的课程表问题） | `cannot_adjudicate` 比例；即兴事实之后被矛盾的次数 |
| Q3 | 住户能否基于亲历形成对玩家的印象，并在新证据下修正？会不会把推测当事实？ | 印象条目是否都引用亲历事件；矛盾印象是否被保留 |
| Q4 | 住户会不会主动找你、主动推进自己的事？ | 玩家站着不动时，地图上住户自发行动和搭话的次数 |
| Q5 | GM 的局势准备（进度钟）能否让十年之间的变化有因果、有伏笔？ | 第 1 个十年埋的事在第 2、3 个十年是否回收 |

这次不做对照组。

## 2. 和游戏端的关系

```
游戏端（Downstairs，现在用模拟器代替）
   │  事件：建了什么 / 执行了什么政策 / 各户满意度 ± / 进入下一个十年
   ▼
V0.2 Harness ── 写进客观事实，推进相关进度钟，通知"感知到"的住户
   │
   ├─ 规划（每个十年一次）：GM 读游戏端状态 → 准备本十年的局势和场景
   ├─ 场景：2D 地图，住户按日程走动，玩家走过去对话
   └─ 角色输出：住户言行，带印象更新
   │
   ▼  回传给游戏端（可选、少量）
   发现的障碍、住户提出的诉求、对话里得知的事
```

**回传（10-28 确认）**：V0.2 可以向游戏端回传 **信息** 和 **小幅的满意度变化**。

- 信息：聊出来的障碍、住户的诉求（相当于原作的拜访揭示障碍）。
- 满意度：小幅、有上限、必须有依据。**光靠说好话不能抵消政策的伤害**；政策对谁有负面影响，那一户的满意度照样大幅下降。

满意度变化规则（数值是 ⚠ 初始默认，测试后调）：

| 来源 | 每户每个十年的上限 | 说明 |
|---|---|---|
| 游戏端政策与设施 | 不限（由游戏端决定，常见 ±5 到 ±20） | V0.2 不能改、不能抵消 |
| 纯对话（倾听、解释、安慰） | **+2 / −5** | 正向很小；说谎被识破、冒犯、失约可以掉得更多 |
| 玩家的实际行动（组织活动、帮忙） | **+5 / −5**，需消耗政策点 | 必须是解决了这户的真实需求才加；需求不对口只加 0–1 |
| 合计（V0.2 回传部分） | **±6** | 无论怎么聊、怎么做，V0.2 一个十年最多让一户变动 6 点 |

硬规则（写在 Harness 里，不靠提示词）：
1. 每条满意度变化都必须引用这户亲历的事件；只有对话事件时，按"纯对话"上限算。
2. 同一户本十年因政策下降了 X 点，V0.2 回传的正向变化不超过 min(6, X/3)。政策伤害最多被缓和三分之一，不会被说没。
3. 满意度变化由角色输出提议（住户自己的判断），Harness 只做裁剪，不替住户决定方向。
4. 回传是一条结构化事件，带原因和证据事件 id，游戏端可以显示"为什么"。

### 2.1 游戏端模拟器

一个侧边面板，代替真正的 Downstairs：

- 当前十年、7 个地块上的设施、已执行的政策
- 五户的满意度（0–100）和四类评价（活力、绿色、整洁、合规）
- 每个十年的 **政策点**（⚠ 默认 3 点）：建设施、执行政策各花 1–2 点；V0.2 里的玩家自由行动也从这里扣（见第 5 节）
- 按钮：建设施、执行政策、手动调整某户满意度、进入下一个十年
- 规则沿用 Downstairs `engine.js` 的卡和可达性判定：比如建了智能社区中心，陈阿姨因为"要手机预约"而用不上，满意度 −；收紧配额，Aisyah 家 −、合规 +
- **剧本**：预置 2–3 套"游戏进程"一键推送（比如"效率优先"：智能中心 → 涨租 → 收紧配额；"人情优先"：留空地 → 保留平价摊位 → 休息亭），方便反复测试同一种局面
- 每条推送都是一条结构化事件，格式就是以后真游戏要发的格式

## 4. 架构

沿用 V0.1 的分工：GM 提案 → Harness 校验提交 → 角色输出 → Harness 校验。

| 调用 | 频率 | 做什么 |
|---|---|---|
| 规划 | 每个十年开始一次；游戏端推来重大事件时可修订一次 | 读游戏端状态与上一代纪要 → 更新势力和住户的目标、进度钟、伏笔，安排本十年的场景 |
| GM | 每轮 | 理解玩家行动 → 操作提案（即兴事实、场景摆放、检定） |
| 角色输出 | 每轮 | 在场住户的言行和叙述，附印象更新 |
| 纪要 | 每个十年结束一次 | 压缩本十年事件与各住户记忆 |

### 4.1 四种存储

| 存储 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| 客观事实 | 事件记录（含感知者）、游戏端推来的事件、即兴确立的细节 | Harness | 按感知范围 |
| GM 推测 | 对玩家角色的性格、动机推测，带证据事件 id | GM | GM、规划 |
| 住户主观认知 | 每户对玩家和对彼此的印象、误解；必须引用亲历事件 | 角色输出 → Harness 校验 | 只有本人 |
| 未执行计划 | 进度钟、伏笔、安排好的场景 | 规划 | 只有 GM |

另存一份现实玩家偏好，只影响节奏，不改世界。

### 4.2 事实四层（修 V0.1 拒绝问题）

| 层 | 例子 | 处理 |
|---|---|---|
| 已确认 | 熟食中心在 3 号地块（游戏端推来的） | 不可改 |
| 普通未定义细节 | 今天楼下有没有人下棋 | GM 直接定，**不设额度**，标"即兴确立" |
| 有后果 | Kumar 会不会中暑 | 走检定或进度钟 |
| 秘密 | 没聊出来的障碍 | 揭示门 |

### 4.3 进度钟

由游戏端事件驱动，不是另一套数值：例如"熟食中心涨租"钟由模拟器里的涨租政策启动，满格后果是 Aisyah、Mei、Kumar 在地图上不再出现在熟食中心。规划可以新增、合并、废弃钟，满格后果必须发生。

## 5. 场景：RPG Maker 式 2D 地图——住户的家（10-28 改，11-02 再改：只做各家）

> **11-02 Polaris："我们准备在咱这里只做每个住户自己的房间和交互，也就是说，办公室和房间走廊之类的不用做。"** 所以地图只有五张：四户的家和 Kumar 他们的宿舍。走廊、电梯厅、楼下 void deck、你的办公室不再是地图，人去不了，但照样可以在话里提到、在旁白里听到；游戏端建在楼下的设施由模拟器记着。换一家用地图上方的门牌（不花时间），规矩和原来进门一样：这户搬来了、家里有人（宿舍随时能去）。下面几条里划掉的是 11-02 以前的做法，具体见设计说明 11.13。

- 地图展示的是 **住户的家**：~~一层组屋走廊连着四户的家门（陈阿姨、林家、Aisyah 家、Mei 家），进门是各自的屋内地图~~ 四户各自的屋内地图（陈阿姨、林家、Aisyah 家、Mei 家），用门牌在各家之间走。家里的陈设反映这户的生活和变化：陈阿姨家的旧象棋盘、林家的玩具和托儿所排队单、Aisyah 家收起来的长桌、Mei 家还没拆完的纸箱。
- **Kumar 和工友不住在组屋里**，他们的"家"是宿舍的一间房 ~~，从组屋走出去到达~~（10-28 确认；11-02 起和各家一样用门牌去，白天 Kumar 在楼里干活，不在宿舍）。这本身就是原作的主题：他们维护这里，但不属于这里。
- ~~走廊和电梯厅是公共空间，住户会在这里碰面；楼下 void deck 和设施只作为窗外/楼下的小地图，游戏端建了什么，从走廊往下看得到。~~ 11-02 起：公共空间不做地图。住户在楼下、出门了的时候不在任何一张图上，GM 知道他们在哪；邻居之间的碰面放在各家里（串门、开斋节开放日、送糕）。
- 格子地图：方向键/WASD 或点击走动；走到住户面前按空格或点击开始对话。
- **对话框里自由输入**，不做选项菜单。
- GM 每个场景输出场景 JSON（时间、天气、谁在哪个格子、在做什么、临时物件），Harness 校验后摆上地图；只能用固定的图块和物件，不从零生成地图。
- 住户按日程在家里、别人家、楼下、外面之间走动 ~~；想找你的住户会来敲你办公室的门或在走廊叫住你~~（11-02 起没有办公室；住户主动来找你要等规划调用，M3）。
- **自由行动**：在地图上可以做对话之外的事，比如组织一次楼下活动、帮人搬东西、陪陈阿姨去诊所。GM 裁定能不能做、后果是什么；**每次这类行动消耗 1 个政策点**（和游戏端共用每个十年的点数），能带来小幅满意度变化（见 2.1 表）。不花点的普通互动（聊天、串门、看看）只影响住户的言行和对你的印象。
- 像素图块和小人用代码画，不依赖外部素材。

## 6. 一局怎么玩

1. 模拟器里选一个剧本，或者手动操作游戏端。
2. 进入第 1 个十年：规划调用准备局势 → 你在各家之间走动、找人说话。
3. 游戏端推来事件（如"建了智能社区中心"），住户在接下来的场景里有反应。
4. 十年结束：纪要 → 游戏端进入下一个十年 → 重复。
5. 第 3 个十年结束：Harness 列事实，GM 写尾声，每户对你说一句话。

## 7. 界面与语言

- 主画面是地图，对话框叠在下方。
- 侧面板：游戏端模拟器、住户（你知道的事；研究者视图下多"他们怎么看你"）、时间轴、检查器（每次调用的提示词、原始输出、实际回答的模型、四种存储的差异）、真相（默认锁）。

## 8. 技术

- 新目录 `prototype-v0.2/`，V0.1 不动。免构建的静态 HTML/JS，双击可开，可发布到 claude.ai。
- 模型：claude.ai 上用浏览者自己的账号，指定 `claude-sonnet-5-5`（设置里可换 Opus），日志记下实际回答的模型，退回默认档位时标红。
- 复用 V0.1 的模型层、事件记录、揭示门、重写流程；复用 Downstairs 的卡、住户、可达性判定（放进模拟器）。
- **以后接入游戏**：规则层不碰界面；对外接口 `createSession(world)`、`pushGameEvent(event)`、`act(text)`、`advanceDecade()`、`getView(perceiver)`、`exportLog()`；住户、卡、地块用 Downstairs 的字段名和 id。真游戏接入时，用它的事件替换模拟器即可。
- `node --test` 覆盖：存储隔离、印象必须引用亲历事件、钟满格必发生、即兴事实不可改、游戏端事件格式。
